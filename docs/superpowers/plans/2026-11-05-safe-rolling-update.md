# 安全滚动更新实施计划

目标：保留双节点轮询，升级失败不能继续重建另一节点；等待旧连接结束，不强行断流

设计：沿用 cpr update 入口，增加 Python 标准库执行器。先校验镜像版本并固定镜像 ID，再逐节点执行 Nginx down、平滑 reload、等待旧 worker 退出、重建、健康及版本检查、恢复流量。默认排空 600 秒、启动检查 300 秒，超时停止。长连接及同一 Nginx 上其他站点可能延长排空；不强杀 worker

相比直接重启，这会推迟部分升级，但能保护旧请求。失败节点保持摘流，另一节点保持在线；不自动回滚数据库或在未验证迁移兼容性时回滚镜像

- [x] 增加执行器和隔离测试：排空超时不重建、启动失败不更新下一节点、配置校验失败恢复文件、固定镜像 ID、重复执行锁
- [x] cpr update 接入执行器；文档说明参数、限制、失败恢复与检查入口
- [x] 在隔离环境验证 Nginx 平滑 reload 和故障路径，审查后部署脚本；生产执行只读预检，已运行相同镜像时跳过重建

验证：Python unittest、bash -n、git diff --check；生产 cpr update --check、同版本无操作检查及双节点健康接口

验证结果：12 项单元测试通过；隔离 Nginx 实测长请求在 reload 后保持、排空超时不中断、请求结束后排空成功。服务器 bash 语法及只读预检通过，同镜像 update 跳过双节点重建。独立审查发现的配置覆盖风险已增加预期内容校验和测试。

取舍：等待全部旧 Nginx worker，其他站点长连接也可能阻止本次升级；保持服务优先，不强杀进程。未在生产强制重建当前相同镜像。
